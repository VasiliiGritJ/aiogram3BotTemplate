# Этап 0 — воспроизводимый локальный запуск на Windows / Python 3.12

## Цель

Довести исходный шаблон до воспроизводимого локального запуска на Windows с Python 3.12, не меняя бизнес-логику бота.

Рабочая ветка: `develop/fitness-coach-foundation`.

Перед работой прочитать:
- `AGENTS.md`
- `PROJECT_SPEC.md`
- `ROADMAP.md`

## Что нужно сделать

1. Синхронизировать локальный репозиторий с GitHub и перейти на ветку `develop/fitness-coach-foundation`.
2. Проверить доступность Python 3.12.
3. Создать локальное виртуальное окружение `.venv` в корне проекта, если его ещё нет.
4. Убедиться, что `.venv/` и `storage/.env` игнорируются Git. Не публиковать секреты.
5. Установить зависимости из `storage/requirements.txt` в `.venv`.
6. Если установка зависимостей падает из-за конфликтов — не подбирать версии вслепую. Зафиксировать точную ошибку и предложить минимальное обоснованное исправление.
7. Проверить импорт/стартовую конфигурацию проекта без подключения YooKassa.
8. Не изменять и не удалять существующий `db.db` без необходимости.
9. Не запускать платежные сценарии.
10. Подготовить проект к запуску до единственного ручного шага владельца: создание локального `storage/.env` с `BOT_TOKEN`.
11. После появления токена локально запустить `python bot.py` из корня проекта и проверить `/start` и кнопку профиля.
12. Зафиксировать найденные проблемы первого запуска и минимальные исправления в рабочей ветке. Не менять продуктовую логику ради косметического рефакторинга.

## Ограничения

- Не коммитить `BOT_TOKEN`, `.env`, платежные ключи или другие секреты.
- Не подключать YooKassa на этом этапе.
- Не делать merge в `main`.
- Не удалять пользовательские данные.
- Не переписывать архитектуру без необходимости для первого запуска.
- Сетевые действия и установка зависимостей допустимы только в объёме, необходимом для этого этапа.

## Критерии готовности

Этап считается завершённым, когда:

- `.venv` работает на Python 3.12;
- зависимости устанавливаются воспроизводимо;
- секреты гарантированно игнорируются Git;
- бот стартует локально из корня проекта с валидным локальным `BOT_TOKEN`;
- `/start` отвечает пользователю;
- профиль открывается;
- пользователь может сохраняться/читаться из SQLite;
- YooKassa не требуется для запуска;
- все необходимые исправления находятся только в рабочей ветке/PR и описаны понятным языком.

## Ручное участие владельца

Владелец не должен передавать токен в чат или GitHub.

Единственное обязательное ручное действие на этом этапе — локально вставить `BOT_TOKEN` в `storage/.env`, когда агент дойдёт до этой точки.
