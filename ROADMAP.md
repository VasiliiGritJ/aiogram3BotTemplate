# ROADMAP.md

## Принцип дорожной карты

Развиваем проект по вертикальным, проверяемым этапам. Каждый этап должен оставлять приложение в запускаемом состоянии. Не перескакивать к AI, оплате или production-инфраструктуре, пока не проверен предыдущий фундамент.

Статусы:

- `[ ]` — не начато;
- `[~]` — в работе;
- `[x]` — завершено и проверено.

FSM-fix commit `8a0e87f` вошёл в merge commit `350cf9792e8ff280db55b8678ccf3eb8e7da4575`, который запушен в `develop/fitness-coach-foundation`.

## Этап 0. Зафиксировать основу проекта

Цель: убедиться, что исходный шаблон воспроизводимо запускается локально на Windows/Python 3.12.

- [ ] Создать локальное `.venv`.
- [ ] Проверить, что `.venv/` игнорируется Git.
- [ ] Установить `storage/requirements.txt` без самовольного изменения версий.
- [ ] Зафиксировать ошибки/конфликты зависимостей, если они есть.
- [ ] Создать безопасный `.env.example` без реальных секретов.
- [ ] Пользователь вручную создаёт `storage/.env` с `BOT_TOKEN`.
- [ ] Запустить исходный `python bot.py` из корня проекта.
- [ ] Проверить `/start` и профиль в Telegram.
- [ ] Убедиться, что новый пользователь сохраняется в SQLite.

Критерий готовности: исходный бот запускается локально и отвечает пользователю без YooKassa.

## Этап 2. Профиль и onboarding фитнес-пользователя

Цель: новый пользователь проходит анкету и получает постоянный профиль.

- [ ] Спроектировать таблицу/поля фитнес-профиля.

- [ ] Поля первой версии: возраст, пол, рост, вес, цель, опыт, тренировок/неделю, оборудование/зал, длительность, ограничения.
- [ ] Валидация числовых значений и понятные сообщения об ошибках.
- [ ] Возможность просмотреть профиль.
- [ ] Возможность изменить отдельные параметры без полного повторного onboarding.
- [ ] Отдельно хранить дату регистрации и бизнес-данные доступа.
- [ ] Добавить тесты сохранения/редактирования профиля.

Критерий готовности: `/start` нового пользователя приводит к завершённому профилю, который сохраняется между перезапусками бота.

## Этап 10. AI-слой

Цель: добавить персонального тренера поверх уже работающих данных и правил.

Не начинать раньше, чтобы AI не маскировал отсутствие нормальной бизнес-логики.

Возможности первой AI-версии:

- [ ] объяснение упражнения простыми словами;
- [ ] краткая мотивационная/контекстная обратная связь после тренировки;
- [ ] объяснение, почему система предложила изменение нагрузки;
- [ ] аккуратная персонализация плана в пределах разрешённых упражнений и правил;
- [ ] ответы на простые вопросы о текущем плане.

Ограничения:

- [ ] AI не меняет статус оплаты;
- [ ] AI не удаляет историю;
- [ ] AI не ставит диагноз;
- [ ] структурированные изменения валидируются обычным кодом перед записью в БД;
- [ ] API-ключ хранится только в окружении.

Критерий готовности: AI улучшает UX, но отказ AI-провайдера не разрушает данные или основное тренировочное ядро.

## Отложено намеренно

До отдельного продуктового решения не добавлять:

- анализ фото/видео техники;
- CV/pose estimation;
- медицинский модуль;
- wearables;
- сложную социальную механику;
- сложную геймификацию.
